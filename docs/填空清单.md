# 部署前填空清单

> 目的：把代码里 4 处占位符换成真实值，填完即可部署跑通。
> 填写顺序从上到下；#2~#4 需要商户号与 API 密钥，未办妥时先只填 #1。

## 一、必须填的 4 处

| # | 文件位置 | 字段 | 填什么 | 在哪查 |
|---|---|---|---|---|
| 1 | `project.config.json:5` | `appid` | 你的小程序 AppID（wx 开头） | 微信公众平台 → 开发管理 → 开发设置 |
| 2 | `cloudfunctions/createOrder/index.js:26` | `MCH_ID` | 微信支付商户号 | 商户平台 → 账户中心 → 商户信息 |
| 3 | `cloudfunctions/createOrder/index.js:27` | `APPID` | 同上，小程序 AppID | 同 #1 |
| 4 | `cloudfunctions/payCallback/index.js:33-37` | `MCH_ID` / `APPID` / `MCH_KEY` / `PROFIT_SHARING_KEY` | 商户号、AppID、APIv2 密钥（32 位，验签用）、分账 API 密钥 | 商户平台 → 账户中心 → API 安全 → 设置 API 密钥（APIv2）；分账密钥如与 v2 密钥不同才另填 |

## 二、填完后的操作顺序

1. 右键 `createOrder` → 上传并部署：云端安装依赖
2. 右键 `payCallback` → 上传并部署：云端安装依赖
3. 右键 `bindReferrer` → 上传并部署
4. 右键 `queryCommission` → 上传并部署
5. 云函数 `payCallback` → 触发器 → 新建 **HTTP 触发器**（鉴权可先关，调试完再开），复制生成的 URL
6. 商户平台 → 开发参数 → 支付结果通知 URL，粘贴第 5 步的 URL
7. 工具里点"编译"，首页下单走一遍

## 三、验证全链路通了的标准

- 云调用日志里 payCallback 返回 XML 中 `return_code=SUCCESS`
- 数据库 `commission_logs` 出现一条 `status=success` 且 `wxProfitsharingOrderNo` 非空的记录

## 四、还没拿到商户号/密钥时的状态

- 只能先完成 #1（AppID）并建云环境、建 4 个集合
- #2~#4 保持占位符不动，**不要部署 payCallback 的 HTTP 触发器**（验签必失败）
- 办妥商户号后按本表回填，再走"填完后的操作顺序"
